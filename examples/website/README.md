# Website Demo for OCW Volume Mounts

This is a complete Hugo static site that demonstrates OCW's volume mounts feature.

## Structure

```
website/
├── content/          # Markdown content (mounted read-only)
│   ├── _index.md     # Home page content
│   └── posts/        # Blog posts
│       ├── _index.md
│       ├── getting-started.md
│       └── another-example.md
├── site/             # Hugo configuration & themes (mounted read-only)
│   ├── hugo.toml     # Site configuration
│   └── themes/
│       └── simple/   # Custom minimal theme
│           ├── theme.toml
│           ├── assets/css/style.css
│           └── layouts/
│               ├── _default/
│               │   ├── baseof.html
│               │   ├── list.html
│               │   └── single.html
│               └── index.html
└── dist/             # Generated output (mounted read-write)
    └── [generated by Hugo during build]
```

## Usage

Run from the examples/ directory:

```bash
# Build the site
ocw -f 17_volumes.yaml build

# Deploy to S3 (requires AWS credentials in ~/.aws)
ocw -f 17_volumes.yaml deploy

# Clean output
ocw -f 17_volumes.yaml clean
```

## Volume Mount Features Demonstrated

1. **Multiple read-only volumes**: `content/` and `site/` are both mounted read-only
2. **Read-write output volume**: `dist/` is the only writable location
3. **Custom mount paths**: Content at `/src/content`, site at `/src/site`, output at `/output`
4. **Mode restriction**: The verify step mounts the rw `dist` volume as read-only for safety
5. **mountPath override**: The verify step mounts `dist` at `/public` instead of `/output`
6. **Job-level inheritance**: All steps in the build job get access to content and site
7. **Step-level additions**: Each step explicitly adds the dist volume when needed
